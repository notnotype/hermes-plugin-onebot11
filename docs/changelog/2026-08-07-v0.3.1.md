# v0.3.1（2026-08-07）

OneBot 11 安全与可靠性收口版本。重点修复关闭生命周期、恢复白名单、reaction 清理和 LLM trigger 状态持久化中的真实边界问题。

## 主要变化

- QueueStore schema 升级到 v8，自动迁移 v7 文件；增加 LLM 判断游标、失败退避和最后错误状态。
- QueueStore 关闭前等待已进入的同步 SQLite 操作完成；关闭后新操作直接 fail-closed，旧 turn 不会访问已关闭连接。
- adapter 断开开始时立即 fencing 活动 lease；关闭后的工具、确认执行、provider request 和 OneBot 出站均拒绝。
- reaction 在 `set=true` 前必须先持久化目标；落盘失败不访问 OneBot。`unset` 成功但本地删除失败时使用最多三次有限退避，恢复路径只尝试 `unset`。
- LLM trigger 对同一批返回 `false` 的消息只判断一次；模型错误、超时和非法 JSON 按失败退避处理；新消息可以提前唤醒判断。
- durable trigger 和 cooldown 恢复在修改 SQLite 状态前重新应用当前群白名单，未授权群不会被恢复或创建 trigger。
- unknown 群管理动作不再按全局 fingerprint 永久阻断；不自动重试，管理员必须重新预览并消费新的确认令牌，响应会提示可能重复执行。
- 同一 image segment 同时含 `file` 和 `url` 时只选择一个实际下载源（优先 URL），诊断字段仍分别保留。

## 不变的安全合同

- 群仍固定使用一个 shared Hermes session；输入消息保持至少一次语义。
- OneBot 非幂等出站不承诺 exactly-once；结果未知时不自动重试，必须人工处理。
- 不修改 Hermes 安装目录，不增加原始 WS spool，不实现 Docker 子代理、OneBot 12 或语义摘要模型。
- `delegate_task` 继续禁止在 OneBot 角色中配置和调用，等待 Hermes 上游 per-turn 工具策略。

## 验证范围

- 本地 Hermes 源码与 site-packages：`178 passed`。
- Ruff：`ruff check .` 通过。
- 纯插件环境：`114 passed, 1 skipped`；跳过项是没有 Hermes `gateway` 依赖的 adapter 集成测试。
- Arch + LLBot 既有联调证据仍对应已部署的 v0.3.0，且严格限制群 `1072992996`、私聊用户 `2056963663`；v0.3.1 新增恢复/关闭/unknown 场景需要重新部署后再验收。
