# v0.4.0（2026-08-07）

本版本把群触发、上下文和权限统一为 TurnAnchor 模型，是有迁移行为变化的功能版本。

## 更新日志

- 每条精确触发消息创建独立 anchor；同群多用户任务在 shared session 中串行 followup，不再合并 authority。
- 自动触发改为保守 anchor selector：只选择一个现存 seq，看不到角色和工具，权限完全继承锚点发送者。
- 当前 batch 结构化保存消息 ID、发送者、role、reply 和媒体标记，锚点之后的消息不会越界。
- turn-start immutable 权限快照；配置工具仍可由 Hermes 调用，但只影响下一 turn。
- 删除 confirmation token；授权写工具直接执行，unknown 后同一 turn 不得重复调用。
- `⏳` 表示 durable queued，`👀` 表示 processing；两种 reaction 都持久记录且只恢复 unset。
- QueueStore schema v9 增加 anchor 边界、kind、authority 来源和 anchor 级失败状态；无法证明 authority 的 v8 状态进入 legacy hold。
- dispatcher 在持久状态转换失败时保留 active heartbeat；恢复单轮失败后继续轮询。
- `/onebot flush` 创建 operator anchor；缺少旧 authority 的 retry 不借管理员身份自动执行。
- 修复多消息 batch 的 outbound marker 聚合、持久 wall-clock cooldown、ContextVar 丢失时的 session/turn 门禁，以及媒体重定向/响应大小/类型魔数边界。

## PR #10 收口补充（尚未合并）

- 过期 `agent_running` lease 增加失败次数并按 2/4/8 秒退避，最多自动恢复 3 次；出站 marker 或阶段未知进入 `uncertain`。
- 每个回复块发送前后重新执行 adapter、白名单和 lease fencing；部分成功不重跑整轮 Agent。
- `resolve retry` 为可验证的 `message`/`operator` anchor 创建新的 request id，保留原 authority、batch 边界和 reaction 状态；legacy hold 不能 retry。
- `maybe_set` reaction 不会因 retry 重置退避或再次 `set=true`；同一消息/类型只保留一条记录，恢复只做有限 `unset`。
- 上下文区分真实 `message_id` 与稳定 `message_key`；hash key 不会进入 OneBot `get_msg` 整数 API。
- OneBot Action POST 禁止 3xx 重定向；未来支持 `hermes_system_error_notice=true` 时不把系统错误通知计入业务 outbound marker。
