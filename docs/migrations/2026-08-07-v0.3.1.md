# OneBot 11 v0.3.1 迁移指南

## 升级前

1. 停止 Hermes gateway。
2. 备份 `HERMES_HOME/onebot11/queue.sqlite3`，以及部署使用的 `config.yaml`。
3. 确认当前 OneBot 白名单仍只包含需要的目标；本次联调约束为群 `1072992996` 和私聊用户 `2056963663`。

## 数据库迁移

- v7 → v8 会在插件启动时自动完成，无需手工执行 SQL。
- v8 新增 LLM trigger 判断游标和失败退避字段；已有 pending 消息不会被删除。
- 如果数据库版本高于 v8，插件会拒绝启动，避免猜测未知 schema。
- 已存在的 `uncertain`/`failed` 消息不会自动重试，必须由超级管理员明确执行 `/onebot resolve retry` 或 `/onebot resolve discard`。

## 配置与行为

- 没有新增必填配置。
- 群 session 合同不变：仍固定为 `shared`，不会自动迁移旧的 `per_user` Hermes session 历史。
- 管理动作结果为 `unknown` 后不会自动重试；需要重新触发预览、获得新的确认令牌，再发送 `/onebot confirm TOKEN`。这可能重复执行，确认前请先检查目标端状态。
- reaction 状态会继续从队列数据库恢复；恢复只发送有限次数的 `unset`，不会重放 `set` 或 Agent turn。
- image segment 同时有 `file` 和 `url` 时只下载一个源，优先 URL；非 URL file 仍必须通过 `get_image` 和显式 `media_source_roots`。

## 升级后检查

1. 启动 Hermes，确认 plugin version 为 `0.3.1`。
2. 查看 `/onebot status`，确认队列、失败/unknown、reaction 清理和 LLM 状态符合预期。
3. 在允许群发送一次 @ 消息，确认共享 session 和 👀 添加/移除链路。
4. 在允许私聊用户发送一次消息。
5. 从非白名单群和非白名单私聊发送测试消息，确认只产生访问拒绝，不入队、不出站。
6. 若存在 `uncertain`，不要把“网络恢复”当作已执行证明；先人工确认 OneBot/QQ 框架状态，再选择 retry 或 discard。
