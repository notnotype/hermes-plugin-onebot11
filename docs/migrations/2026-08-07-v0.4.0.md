# v0.4.0 迁移指南

## 升级前

1. 停止 Hermes，确认没有活动 OneBot turn。
2. 备份 `HERMES_HOME/onebot11/queue.sqlite3` 与 `config.yaml`。
3. 核对 `allowed_groups`、DM allowlist 和 token；联调只允许群 `1072992996` 与用户 `2056963663`。

## 自动迁移

- schema v8/v9 会自动升级到 v10；高于 v10 的未知版本拒绝启动。
- 可证明的一对一 pending trigger 迁移为 message anchor。
- 旧 LLM trigger 不沿用 caller；消息保留并等待新 selector。
- v9 pending anchor 首次 claim 时按当前配置绑定 authority；v9 active、uncertain、failed 或损坏/缺失 authority 快照的记录进入 hold，不能猜测权限。
- 不迁移旧 per-user Hermes session 历史；群仍固定 shared session。

## 行为变化

- `require_mention=false`/`always` 不再直接以当前发送者权限启动 turn；请配置自动 selector，或改用 @/关键词精确触发。
- `llm_trigger` 配置名仍保留，但模型输出从 JSON boolean 改为：

  ```json
  {"anchor_seq": 123, "reason_code": "automatic_request"}
  ```

  无任务返回 `{"anchor_seq":null,"reason_code":"no_request"}`。
- 旧 `/onebot confirm TOKEN` 被移除，已有 token 升级后失效。授权写工具直接执行；请收紧 `roles.*.tools` 后再启动。
- 权限配置变化从下一 turn 生效。当前活动 turn 保留其不可变工具快照。
- `resolve retry` 只对有 authority 快照的 `message`/`operator` anchor 创建新 request id，并迁移原 reaction；缺失 authority 的记录只能 discard 或等待新的明确触发。
- `resolve discard` 不删除 reaction cleanup record；重启只有限恢复 `unset`，不会重放 `set=true`。
- `queued_reaction_emoji_id` 默认 `9203`；不同 QQ 框架若不兼容，可关闭 queued reaction 或显式覆盖。
- 私聊历史和单条消息查询必须逐条属于“当前用户 + 当前机器人”；没有真实数字 OneBot message ID 的 hash key 不能查询 `get_msg`。
- `delegate_task`、`tool_search`、`tool_describe`、`tool_call` 不能配置到 OneBot 角色；tool-search 目录可见不等于当前 turn 获得执行权限。

## 升级后验证

1. `/onebot status` 确认 schema、最早 anchor、blocked/reaction 状态。
2. 两名允许群成员分别 @ bot，确认形成两个 anchor、两个串行 turn 和同一个 shared session。
3. 确认每条消息经历 `⏳ -> 👀 -> cleared`；重启后只清理遗留 reaction，不重放 turn。
4. 用普通用户验证高风险工具拒绝；用受信用户验证精确工具；不在未授权环境执行破坏性群管理动作。
5. 非白名单群和私聊必须无入队、无出站。
