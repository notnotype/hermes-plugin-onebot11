# 权限模型（群聊为主场景）

OneBot 11 主要跑在群聊里,权限分三层设计。核心原则：**白名单群里的用户也不可信任**——不放开 shell/管理权限;能 @ 机器人聊天的人很多,但能用工具、能查数据的人必须被约束住。

## 三层结构

### 1. 网关用户授权层（谁能让机器人响应）

| 场景 | 默认 | 配置 |
|---|---|---|
| 群聊触发 | @ 机器人恒触发 | 关键词触发用 `ONEBOT11_KEYWORD_TRIGGERS`;LLM 判定用 `ONEBOT11_LLM_TRIGGER=true` |
| 群白名单 | 所有群可用 | `ONEBOT11_ALLOWED_GROUPS=群号,群号`（空 = 不限制）;白名单外群消息完全忽略 |
| 群会话 | 一群一会话 | `ONEBOT11_GROUP_SESSIONS_PER_USER=false`;`true` = 群里每用户独立会话 |
| 私聊 | 全部放开 | `ONEBOT11_DM_POLICY=open` |
| 私聊白名单 | — | `ONEBOT11_DM_POLICY=allowlist` + `ONEBOT11_ALLOWED_USERS=QQ,QQ` |
| 私聊关闭 | — | `ONEBOT11_DM_POLICY=disabled` |

> v0.2.0 起 `ONEBOT11_REQUIRE_MENTION` 废弃：@ 机器人恒为触发源;未触发的群消息进入每群消息队列,触发时拼接"自上次触发以来的群聊摘要"（最近 N 条原文 + 更早消息压缩,上限可控）。

### 2. 角色与工具权限层（调用侧约定,非注册侧过滤）

**角色**（二元,`role_of`）：
- 超级管理员 = `ONEBOT11_ADMINS` 列表中的 QQ（一般是机器人 owner 自己）
- 普通用户 = 其余所有人

**工具权限**（调用侧守卫 `check_role_tool_call`）：
- 工具集 = 所有角色许可的**并集**,全部注册、全部对 LLM 可见（缓存友好,不按角色过滤 schema）。
- 调用时按 `ToolContext.user_id → 角色 → 工具是否在 admin-only 表` 判定：
  - `ONEBOT11_ADMIN_TOOLS` 中的工具,普通用户调用 → **不执行**,返回"权限不足:该工具仅管理员可用"给 LLM（LLM 据提示词知道自己越界,转为解释/拒绝）。
  - 空表（默认）= 所有工具普通用户可用。
- 角色权限表会注入普通用户触发时的消息（提示词层面约束 LLM）,越权调用由调用侧守卫兜底——LLM 无法伪造身份（user_id 来自入站会话,非 LLM 参数）。

### 3. 会话范围校验（安全底线,强制生效）

工具只能作用于**发起会话自身**：

- 群里调用 `qq_get_group_msg_history` → 只能查**本群**,传别的群号直接拒绝。
- 群里调用 `qq_get_friend_msg_history` → 拒绝（群会话无权查私聊）+ admin 门禁。
- 私聊调用查询工具 → 只能查**自己**的消息。

这是群聊场景的安全底线：陌生人进群能聊天,但查不到群外数据。

## 群角色感知（v2.1 预留,不在 v0.2 实现）

v2.1 计划通过 `get_group_member_info` 获取发起者在目标群的 role（owner/admin/member）,对**破坏性写工具**（踢人、禁言等,v0.2 不做）按群角色降级。v0.2 用 `ONEBOT11_ADMINS` 列表即可满足,`permissions.py` 已留接口。

## 决策记录

- 为什么工具不按角色过滤注册（并集注册）？—— 工具 schema 随每次 API 调用发送,按角色过滤会导致缓存碎片化;权限移到调用侧,一张 admin-only 表 + 一个守卫函数即可。
- 为什么查询类工具默认不是 admin-only？—— 群聊主场景下,群内查本群消息是常用诉求;隐私边界由「会话范围校验」兜住（查不到群外）。
- 为什么私聊历史默认 admin-only？—— 私聊历史跨会话、涉及他人隐私面,默认收紧,需要时由管理员放开（加入 `ONEBOT11_ADMIN_TOOLS`）。
- 为什么 shell/文件等特权工具永不注册进群聊？—— 白名单群用户不可信任,特权工具不进入本插件的工具集。
